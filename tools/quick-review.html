How to score points

  • Never leave a written answer blank. 69% of points are descriptive/performance and get partial credit per keyword.
  • Sure points first. Answer what you know fast, flag the rest, come back.
  • Short numbered points with exact terms ("transitive dependency", "composition", "Little's law").
  • Calculations: formula → numbers → answer with unit → one-line meaning ("CPI 0.8 = over budget"). Method earns points even if the final number is off.
  • Read "incorrect" in the stem before reading the options.
  • Code: use the language you know best. Clear pseudocode beats broken code.

Reverse engineering = code → design, nothing changed. Reengineering = reverse + restructure + forward.

Data structures

  • Stack LIFO (recursion, undo, DFS). Queue FIFO (BFS, scheduling).
  • Binary tree: level i max 2i−1; depth k max 2k−1; leaves = nodes with 2 children + 1.
  • Traversal of A(B(D,E), C(-,F)): pre A B D E C F · in D B E A C F · post D E B F C A.
  • BST in-order = sorted. Heap = complete tree, parent ≥ children.
  • Infix A*(B+C)-D → postfix A B C + * D -.
  • Hash collisions: chaining or open addressing (linear probing).
  • Doubly linked delete x: x.llink.rlink = x.rlink; x.rlink.llink = x.llink

Binary search: needs sorted data, O(log n), max ⌊log2n⌋+1 comparisons (1,000 items → 10).

Greedy: Kruskal, Prim, Dijkstra. Dynamic programming (stores overlapping subproblems): Floyd-Warshall, knapsack, Fibonacci. Divide and conquer: merge/quick sort. Backtracking: N-Queens.

AI (new in V4.0E)

  • Overfitting = memorizes training data. Fix: more data, regularization, dropout, early stopping.
  • CNN images · RNN/LSTM sequences · Transformer self-attention, parallel (LLMs) · GAN generator vs discriminator.
  • RAG = retrieve documents into the prompt (no retraining). Fine-tuning = retrain weights. Hallucination = confident false output.

Requirements and analysis

  • Functional = what it does. Non-functional = how well (performance, security, availability).
  • Verification = built right (meets spec). Validation = right product (meets needs).
  • DFD: process (circle), data flow (arrow), data store (two lines), external entity (box).
  • Data dictionary: = composed of, + and, [|] choose, { } repeat, ( ) optional.
  • «include» always happens (Withdraw includes Authenticate). «extend» optional (Print receipt).

Design: cohesion and coupling

Cohesion worst → best: Coincidental, Logical, Temporal, Procedural, Communicational, Sequential (output→input), Functional.

Coupling worst → best: Content, Common (globals), External, Control (flag), Stamp (whole struct), Data.

Goal: high cohesion, low coupling. SOLID: Single responsibility, Open/closed, Liskov, Interface segregation, Dependency inversion.

MVC = "separate view, processing and business logic". Others: layered, client-server, pipe-and-filter, broker, event-driven, microservices.

UML

  • Multiplicity is read at the far end: Person 1 — 0..* Order.
  • Activity: start ●, actions, decision ◇ with [guards], fork/join bars, swimlanes, end ◉.
  • Sequence: lifelines, activation bars, sync (filled arrow) vs async, return (dashed), alt/opt/loop.

Testing

  • Unit → Integration → System → Acceptance. Alpha at developer's site; Beta at users' sites.
  • Stub = fake lower module (top-down). Driver = fake caller (bottom-up).
  • White-box: statement < branch < condition < MC/DC < multiple condition. V(G) = E − N + 2 = decisions + 1.
  • Black-box: equivalence partitioning (one value per class), boundary values (18–60 → 17, 18, 19, 59, 60, 61), decision table, state transition.
  • Regression = re-test after change. TDD = red → green → refactor.

Maintenance, Git, licenses, MSA

  • Maintenance: Corrective (bugs), Adaptive (new OS or law), Perfective (new features, largest share), Preventive (refactor).
  • SCM: identification, version control, change control (CCB), status accounting, audit. git pull = fetch + merge.
  • Licenses: GPL strong copyleft (release source if distributed), AGPL (even as a service), LGPL/MPL weak, MIT/BSD/Apache 2.0 permissive.
  • Microservices: API gateway, service discovery, circuit breaker (stop calling a failing service). Containers share the host kernel.

Code-reading traps

  • Java: Parent p = new Child() → methods use Child, fields use Parent. == compares references; use equals(). For-each can't change array elements.
  • C: 7/2 = 3; *(p+2) = p[2]; i++ uses then adds; switch falls through without break.
  • Python: 7//2 = 3, -7//2 = -4, 2**3 = 8; s[1:4] stops before 4; [::-1] reverses.

M2 Data Management 265 points · 6 minutes

Database basics

  • 3 levels: external (user views) · conceptual (whole DB) · internal (storage).
  • Logical independence = external↔conceptual. Physical independence = conceptual↔internal.
  • Degree = columns, cardinality = rows. A × B: degrees add, cardinalities multiply.
  • Super key unique · Candidate key unique + minimal · PK = chosen candidate, NOT NULL · FK references a PK.
  • Integrity: entity (PK not null/unique), referential (FK matches a PK or is null), domain.

ERD and modeling

  • M:N → associative table with both FKs (Student–Enrollment–Course).
  • Chen: entity box, relationship diamond, attribute oval; double oval = multi-valued; dashed = derived; double box = weak entity.
  • Supertype/subtype to tables: one table + type column · subtype tables only · one table per type (subtype PK = supertype PK, also FK).

Normalization

1NFAtomic values
2NFNo partial dependency (on part of a composite key)
3NFNo transitive dependency (A→B→C)
BCNFEvery determinant is a candidate key
4NF / 5NFNo multi-valued / join dependency

Anomalies: insertion, deletion, update. Example: ORDER(order_no, prod_id, cust_name, …) → split ORDERS, CUSTOMER, PRODUCT, ORDER_LINE.

Denormalization = add redundancy for read speed (derived columns, summary tables, merge tables).

Indexes and views

  • B-tree default (equality and ranges) · Bitmap low-cardinality columns in DW · Hash exact match · Clustered = rows stored in order (one per table).
  • Index not used: LIKE '%son', functions on the column. Indexes slow INSERT/UPDATE/DELETE.
  • View = stored query, no data (except materialized); security + logical independence; GROUP BY views not updatable.

SQL facts

  • DDL: CREATE, ALTER, DROP, TRUNCATE · DML: SELECT, INSERT, UPDATE, DELETE · DCL: GRANT, REVOKE · TCL: COMMIT, ROLLBACK, SAVEPOINT.
  • WHERE = selection σ; SELECT list = projection π; ÷ = division ("related to all").
  • Only DELETE can be rolled back. TRUNCATE/DROP auto-commit.
  • Run order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.
  • WHERE filters rows, HAVING filters groups (aggregates).
  • Aggregates ignore NULL except COUNT(*). AVG(100,200,NULL,300) = 200.
  • > ALL = greater than max; > ANY = greater than min.
  • 5 emp (1 without dept) × 3 dept (1 empty): inner 4, left 5, full 6, cross 15.

Trap: NOT IN with a subquery containing NULL returns no rows. Use NOT EXISTS.

Transactions and concurrency

  • ACID: Atomicity (undo), Consistency, Isolation (concurrency control), Durability (logs).
  • Dirty read = uncommitted data · Non-repeatable = same row changes · Phantom = new rows appear · Lost update = overwrite.

2PL: growing then shrinking phase → serializable, but deadlock still possible. Shared locks compatible; exclusive conflicts with all. Deadlock needs mutual exclusion, hold and wait, no preemption, circular wait.

Recovery and backup

  • Committed after last checkpoint → REDO; not committed → UNDO; committed before → nothing.
  • WAL: write the log before the data page.
  • 2PC: prepare/vote, then commit or abort; any NO → abort all; blocking if coordinator fails.
  • Restore: Differential = full + latest differential. Incremental = full + every incremental in order. Archive logs → point-in-time recovery.
  • 24×7 answer: hot backups, weekly full + daily differential + archive logs, off-site copy, test restores.

Data warehouse and mining

  • DW (Inmon): subject-oriented, integrated, time-variant, non-volatile.
  • OLTP = current, normalized, many small writes. OLAP = history, denormalized, big reads.
  • Star = fact + denormalized dimensions. Snowflake = normalized dimensions (more joins).
  • OLAP: roll-up (coarser), drill-down (finer), slice (one value), dice (ranges), pivot.
  • ETL = extract, transform, load. Data mart = subject subset.
  • A→B: support = P(A∧B), confidence = P(A∧B)/P(A), lift = confidence/P(B) (>1 positive, =1 independent).

Big data, NoSQL, data for AI

  • 3V: volume, velocity, variety (+ veracity, value). HDFS: NameNode + DataNodes, 3 replicas. Spark = in-memory.
  • CAP: Consistency, Availability, Partition tolerance (pick 2 during a partition). BASE = eventually consistent.
  • NoSQL: key-value (Redis) · document (MongoDB) · column-family (Cassandra) · graph (Neo4j, social networks).
  • Data lake = raw data, schema-on-read. DW = schema-on-write.
  • Min-max (x−min)/(max−min); z-score (x−mean)/sd; one-hot for categories; vector DB = embeddings + similarity search (RAG).

Operating systems

  • States: new → ready → running → terminated; running → waiting (I/O) → ready; running → ready (timeout).
  • FCFS (convoy) · SJF (lowest average wait, starvation) · SRT · Round Robin (quantum) · Priority (+aging) · HRN = (wait + service)/service.
  • Semaphore: P/wait decrements (may block), V/signal increments.
  • Deadlock avoidance = Banker's algorithm (safe state).
  • Paging → internal fragmentation; segmentation → external. Thrashing = too much paging.
  • Page replacement: FIFO (Belady's anomaly), LRU, OPT (best, theoretical).

Architecture and availability

  • 3-tier: web server (static) → WAS (logic) → DB.
  • Hypervisor Type 1 bare-metal (ESXi, Hyper-V, Xen, KVM) · Type 2 hosted (VirtualBox). Containers share the host kernel.
  • Scale up = bigger server; scale out = more servers.
  • RTO = max downtime; RPO = max data loss.

Cloud

Cryptography

  • Symmetric (AES, DES 56-bit, SEED, ARIA): fast, key-distribution problem. Asymmetric (RSA = factoring, ECC, DH = key exchange).
  • Encrypt for secrecy with the receiver's public key. Sign the hash with the sender's private key; verify with sender's public key.
  • Hash (SHA-256): one-way, fixed length. HMAC = integrity + authentication, no non-repudiation (shared key).
  • ECB leaks patterns. Passwords: salt + bcrypt. CA issues X.509 certificates.

Trends, ethics and IP

SQL: groups, joins, subqueries

-- members with more than 3 loans in Oct 2026
SELECT m.member_id, m.name, COUNT(*) AS cnt
FROM member m JOIN loan l ON l.member_id = m.member_id
WHERE l.loan_date >= DATE '2026-10-01'
  AND l.loan_date <  DATE '2026-11-01'
GROUP BY m.member_id, m.name
HAVING COUNT(*) > 3
ORDER BY cnt DESC;

-- rows with no match (never borrowed)
SELECT b.title FROM book b
WHERE NOT EXISTS (SELECT 1 FROM loan l WHERE l.book_id = b.book_id);

-- above own department's average (correlated)
SELECT e.name FROM emp e
WHERE e.salary > (SELECT AVG(salary) FROM emp x
                  WHERE x.dept_id = e.dept_id);

-- NULL check: never "= NULL"
WHERE return_date IS NULL

Binary search (Python)

def search(a, key):
    low, high = 0, len(a) - 1
    while low <= high:
        mid = (low + high) // 2
        if a[mid] == key: return mid
        if a[mid] < key: low = mid + 1
        else: high = mid - 1
    return -1
